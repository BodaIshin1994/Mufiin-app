# Muffin · Заказ кофе — деплой в продакшн

Это уже не демо-прототип, а рабочее веб-приложение с настоящей базой данных
(Firebase Firestore) и мгновенной синхронизацией между сотрудником и бариста —
без перезагрузки страницы. Устанавливается на телефон как обычное приложение
(PWA), без App Store и без ревью.

Всё бесплатно на тарифе Firebase Spark для масштаба одного офиса (лимиты —
50 000 чтений и 20 000 записей в Firestore в день, этого с запасом хватит на
сотни заказов ежедневно).

## Что понадобится

- Google-аккаунт (для Firebase Console)
- Node.js 18+ на компьютере, с которого будете деплоить: https://nodejs.org
- 15–20 минут

## Шаг 1. Создать проект Firebase

1. Откройте https://console.firebase.google.com → **Add project** (Добавить проект).
2. Назовите проект, например `muffin-coffee`. Google Analytics можно отключить — не нужен.
3. Дождитесь создания проекта.

## Шаг 2. Включить Firestore Database

1. В боковом меню: **Build → Firestore Database → Create database**.
2. Выберите **Production mode** (правила безопасности уже лежат в `firestore.rules`, зальём их отдельно на шаге 5).
3. Регион — ближайший к Баку, например `eur3 (europe-west)`.

## Шаг 3. Включить анонимный вход

1. **Build → Authentication → Get started**.
2. Вкладка **Sign-in method** → включите провайдер **Anonymous**.

Сотрудникам не нужно ничего вводить — приложение само незаметно
авторизуется при открытии. Это лишь базовая защита от случайных ботов из
интернета, а не полноценный логин — см. раздел «Что доработать» ниже.

## Шаг 4. Получить конфиг веб-приложения

1. Главная страница проекта → значок **`</>`** (Add app → Web).
2. Название — любое, например `muffin-web`. Firebase Hosting подключать здесь не обязательно, сделаем через CLI.
3. Скопируйте объект `firebaseConfig`, который покажет Firebase.
4. Откройте файл `firebase-config.js` из этого проекта и вставьте свои значения вместо `REPLACE_ME`.

## Шаг 5. Установить инструменты и задеплоить

В терминале, в папке проекта (там, где лежит `index.html`):

```bash
npm install -g firebase-tools
firebase login

# привязать эту папку к вашему проекту Firebase:
firebase use --add
# выберите muffin-coffee (или как вы его назвали) из списка

# опубликовать сайт и правила базы данных:
firebase deploy --only hosting,firestore:rules
```

По завершении команда выведет ссылку вида `https://muffin-coffee.web.app` —
это и есть рабочее приложение. Она бесплатна и работает на HTTPS из коробки
(обязательное условие для PWA).

## Шаг 6. Установить как приложение на телефон

**iPhone (Safari):** открыть ссылку → кнопка «Поделиться» → **«На экран
„Домой“»**.

**Android (Chrome):** открыть ссылку → появится кнопка **«⤓ Установить»**
прямо в шапке приложения (либо через меню Chrome → «Установить приложение»).

После установки иконка Muffin появится на рабочем столе и будет открываться
как обычное приложение, без адресной строки браузера.

## Что дальше можно улучшить

Эти вещи не входят в прототип, но стоит держать в голове перед тем, как
раскатывать на весь офис:

- **Нормальная авторизация сотрудников** — сейчас это анонимный вход,
  имя вводится вручную. Можно подключить Firebase Auth по корпоративной
  почте (`@abc-telecom.az`), тогда «Мои заказы» будут привязаны к аккаунту,
  а не к введённому имени.
- **Push-уведомление бариста и сотруднику** о новом заказе / о готовности —
  через Firebase Cloud Messaging (сейчас нужно держать вкладку открытой).
- **Меню и цены** сейчас зашиты в `app.js` — при желании вынести в отдельную
  коллекцию Firestore, чтобы кофейня могла менять их без разработчика.
- **Свой домен** вместо `*.web.app` — Hosting → Add custom domain, если у
  компании 67 (`abc-telecom.az`) есть поддомен для этого.
- **Если всё же захочется в App Store/Google Play** — это готовое PWA можно
  обернуть в нативную оболочку (например, через Capacitor или PWABuilder)
  почти без переписывания кода и опубликовать уже тогда. Но для внутреннего
  инструмента одного офиса это обычно не нужно — см. предыдущее сообщение.

## Локальная проверка перед деплоем (необязательно)

```bash
npx firebase-tools emulators:start --only hosting
# или просто: npx serve .
```
и открыть `http://localhost:5000` (порт зависит от инструмента).
